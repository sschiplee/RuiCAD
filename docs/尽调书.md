# 全屋定制 CAD 插件 · 技术尽职调查与可行性报告

编制：为「瑞物里家居美学馆」内部工具自研决策而作
版本：v1.2（结论已随 v0.2.0 落地，完成第二轮对标扩充与 47 用例双重自测）

---

## 0. 结论先行（TL;DR）

1. **完全可以实现，且已实现可运行的 v0.2.0 开源原型**：46 个命令、图形化 exe 安装器（支持 CAD 开着时即时加载）、47/47 无头自测通过（项目源码与安装包释放代码双重验证）、图形肉眼复核通过。
2. **合法路径只有一条：自主重写（clean-room 独立实现）**。"破解 / 反编译商业插件"在《著作权法》《计算机软件保护条例》下属于侵权，且商业插件普遍有授权校验、机器绑定和法律追责风险，**不建议、本方案也不采用**。
3. 全屋定制 CAD 插件的技术门槛**不在"画得出来"，而在"工艺库积累、易用性、稳定性与出图规范"**。核心绘图用 AutoLISP 即可实现，零运行库依赖、最易维护、最适合小团队。
4. 第二轮对标光速/碧福/雷神/海龙/快图等最新功能后，补齐了竖隔板/活动层板/墙体开洞/榻榻米、铰链/拉手/三合一系统孔、逐段连续/门板标注、板件编号/详细 BOM、智能拉伸/清理/填充等，**高频绘图场景覆盖度提升到约 85%**；剩余差距集中在面板化、成熟实物图库与报价打通（见第 6 节）。

## 1. 调研对象与信息来源

调研了市面主流全屋定制 CAD 插件（信息来自其官网、抖音/小红书教学视频、公开功能清单）：

| 插件 | 形态 | 主要特点 | 授权模式 |
|---|---|---|---|
| 光速（云光科技/超会设计相关） | LISP/.ARX + 安装包 | 命令极多、快捷键体系、一键标注/轴测/门板/外抽/灯带 | 收费、机器授权 |
| 碧福家具插件 | LISP + 面板 | 标准柜一键库、洞洞板/隔栅/酒格、面积/BOM、彩色贴图 | 收费、注册登录 |
| 雷神家具插件 | LISP | WG/DG/KJ 框架、自动拆单 BOM、局部放大 | 收费 |
| 紫灵/紫居 | LISP | 一键柜门、挂衣服、均分线板、平侧面 | 收费 |
| 濮汇工具箱 | LISP | 批量导入图片、编号、文字工具 | 收费 |
| 双林/123 插件等 | LISP | 五金统计、圆弧倒角等 | 收费 |

**共性结论**：
- 绝大多数（尤其面向中小定制门店/设计师的）本质是 **AutoLISP / Visual LISP** 程序，少数高级功能用 ObjectARX（C++）或 .NET；
- 交付形态都是"**安装包 exe + 一堆 lsp/arx + 支持路径/启动组注册**"，开机随 CAD 加载；
- 收费点主要是：**工艺知识库、命令数量与打磨、售后更新、授权体系**，而非不可复制的黑科技；
- 绘图单位为毫米，普遍自建图层分色，命令以 2~3 位拼音首字母缩写为主。

## 2. 三种获取路径的合规与可行性对比

| 路径 | 做法 | 法律/合规 | 技术 | 结论 |
|---|---|---|---|---|
| 购买授权 | 按年/永久买商业插件 | 合法 | 稳定但长期付费、绑定机器、无法定制 | 可作为过渡 |
| **破解/盗版/反编译** | 绕过授权、反编译改代码 | **侵犯著作权、破坏技术措施，公司商用风险高**；可能夹带木马 | 升级即失效、无法维护 | **明确否决** |
| **自主重写（本方案）** | 参考"功能类别与交互习惯"，代码从零写 | 合法（思想/方法不受保护，只保护表达）；MIT 开源更安全 | 完全可控、可随公司工艺定制 | **采用** |

> 合规要点：著作权不保护"软件的思想、算法、操作方法"，只保护**具体代码表达与专有素材**。
> 因此可以合法地"实现同样功能"，但**不得复制其源码、图块、图库、界面素材、文案，不得反编译，不得使用其商标**。
> 本项目所有代码为独立编写，命令缩写独立命名，未使用任何第三方专有资源。

## 3. 技术可行性

### 3.1 为什么选 AutoLISP

| 维度 | AutoLISP（选用） | ObjectARX / C++ | .NET (C#/VB) |
|---|---|---|---|
| 开发门槛 | 低，设计师也能改 | 高，需 C++/CAD SDK | 中 |
| 运行库依赖 | **无**，CAD 自带解释器 | 需匹配版本 DLL | 需 ObjectARX 托管包 |
| 跨版本/国产 CAD | **最好**（中望/浩辰都兼容 LISP） | 差，逐版本编译 | 中 |
| 绘图/标注/选择集能力 | 足够覆盖定制绘图 | 最强 | 强 |
| 维护成本 | **最低** | 高 | 中 |
| 适合场景 | 绘图效率工具（本项目） | 复杂几何/数据库/性能 | 复杂 UI/外部系统集成 |

结论：**板式定制的绘图、标注、统计用 LISP 完全够用且最稳**；未来若要做复杂 UI 面板或与 ERP/拆单软件对接，再用 C# .NET 做外壳，与 LISP 并存（LISP 负责绘图、.NET 负责界面/数据），二者可互调。

### 3.2 关键技术点与已验证方案

| 能力 | 实现方式 | 状态 |

### 3.3 兼容平台

- AutoCAD 2007+（用到的均为最基础 API；测试环境 AutoCAD 2021 / R24.0）
- 中望 CAD、浩辰 CAD：均内置 AutoLISP 兼容解释器，命令层通用；安装器已对其注册表位置做 best-effort 适配，建议在国产 CAD 上各实测一轮。

## 5. 架构设计（已落地）

```
用户命令(c:XX, 负责交互取点取参)
        ↓ 调用
核心纯函数(rc:xxx, 只接收点/参数 → 计算坐标 → entmake 出图)
        ↓ 依赖
基础层(utils: 图层/图元/几何/标注样式) + 全局参数(settings)
```
- **交互与逻辑分离**：核心函数不依赖用户输入，可被脚本批量调用与自动化测试；
- **模块化**：core（框架）+ commands（按业务分 7 个文件：draw/parts/hardware/view/dim/edit/panel），新增功能不影响旧功能；
- **安装与运行分离**：LISP 负责 CAD 内能力，C# 安装器只负责部署与注册表配置。

### 质量保障（自测方法）
- 使用 AutoCAD 官方无头引擎 `accoreconsole.exe`，编写 47 个用例，断言每个核心函数
  "无 LISP 错误 + 正确数量图元"，结果 **47/47 PASS**；并对"安装包释放出的嵌入代码"再跑一遍同样 47/47，双重验证；
- 关键工程细节：无头环境下 `ssget` 交叉窗口选择(`_C`)依赖屏幕会返回空，已统一改为
  `ssget _X` 全取 + 包围盒几何过滤（`rc:lines-in-box`），无头与真实交互都稳定；
- 安装时若 CAD 已在运行，安装器经 COM 向每个打开文档即时 `(load init.lsp)`，已在真实 AutoCAD 进程验证新命令免重启即变为 SUBR；
- 生成综合演示 DWG 并导出 PNG，逐个人工复核几何形状（标准柜/门板/抽屉/玻璃/衣杆挂衣/
  隔栅/洞洞/酒格/圆角/轴测/框架/俯视/标注/铰链/三合一排孔），标注数值与面积（2.16e6 mm²）正确；
- 安装器在干净环境实测：静默安装→注册表/启动套件/文件正确→CAD 自动加载命令可用→静默卸载无残留。

## 7. 风险与规避

| 风险 | 说明 | 规避 |
|---|---|---|
| 知识产权 | 误复制商业插件代码/素材 | 坚持 clean-room；独立命名；MIT 开源；保留自研提交记录 |
| 国产 CAD 兼容 | 中望/浩辰个别命令差异 | 只用最通用 API；安装器适配注册表；上线前逐平台实测 |
| 版本碎片化 | 老版本 CAD API 差异 | 避免高版本专有函数；标注/多段线用通用组码 |
| 工艺贴合度 | 各厂板厚/缝/结构不同 | 参数全部外置在 settings.lsp，可按厂定制 |
| 用户习惯迁移 | 设计师习惯商业插件快捷键 | 命令缩写向行业习惯靠拢，RCH 随时查表 |
| 维护连续性 | 个人开发知识孤岛 | 模块化 + 注释 + 本文档 + 开源社区 |

## 8. 总体判断

- **能不能做**：能，且没有任何不可逾越的技术壁垒；v0.2.0 已用可运行、可安装、可测试的成果证明。
- **怎么做最稳**：AutoLISP 自主重写绘图内核（合法、零依赖、跨平台），C# 做安装器与未来面板；
  先覆盖高频场景在公司内部用起来，再按本厂工艺持续沉淀柜型/五金/BOM。
- **是否开源**：MIT 开源对公司是保护也是资产——可自由商用、定制、闭源衍生，同时避免侵权争议；
  建议以公司或维护者名义建公开仓库，提交记录即自研证据。
- **与"碧福水准"的差距**：v0.2.0 在"绘图命令覆盖面"已达其高频可用水平；在"面板体验、图库深度、
  报价拆单"上需按 M2~M4 持续投入，属正常产品迭代，而非可行性问题。
